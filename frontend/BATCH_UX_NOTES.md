# מחויבים ל־100 — שולחן התחייבויות וביקורת ממוקדת

עדכון Batch Export: נוסף תור דפדפן סדרתי של עד 30 קבצים וייצוא משותף של כל
עמודי הסינון או שורות מסומנות. חלקי המסמך שלהלן שמתארים חסימת בחירה מרובה
או היעדר ייצוא משותף מתעדים את הגרסה הקודמת. המימוש, גבולות האבטחה,
בדיקת timeout והמגבלות העדכניות מתועדים ב־`docs/batch_export_and_upload_audit.md`
בעץ המקורי. התור אינו מנגנון עיבוד רקע עמיד.

עדכון: נוספה תמיכה באישור אנושי כולל לטופס, יחד עם שינויי שרת בענף המקורי.
המדיניות והאחסון מתועדים ב־`docs/form_approval.md` בעותק המקורי. מגבלת שבע
החלטות השדה המתוארת להלן מתייחסת לשרת הישן; מול שרת תומך אפשר לפתור חריגים
ואז למסור הצהרה אנושית אחת לטופס. זו אינה קבלה אוטומטית או שבעה אישורים סמויים.

כל השינויים במשימה הזאת נמצאים ב־`storage/premium-ui-worktree`, בענף
`feat/premium-ui-redesign`. לא בוצעו commit, push או החלפת ענף. קוד השרת,
מסדי נתונים, migrations, הגדרות וסודות לא שונו. התלויות המותקנות הועתקו
לתוך ה־worktree במקום junction, כדי שגם מטמון הבנייה לא ייכתב לעותק המקורי.
לא הותקנו חבילות.

## מה עובד בפועל

- טבלת התחייבויות עם שבעת השדות העסקיים, מזהי מסמך/טופס ומצב ביקורת.
  לכל מספר התחייבות נבדל שורה; ללא מספר נשארת שורה עם תא ריק. אין חיתוך
  רווחים, המרה למספר, או איחוד בין טפסים/מסמכים.
- מספרים מרכזיים מרובים חוזרים במלואם בכל התחייבויות הטופס. לא נוצרים
  קשרים חדשים בין דגימות להתחייבויות.
- השולחן מרכז טפסים שנקלטו בזה אחר זה, או נטענו מרשומות שמורות. פתיחת
  מסמך טוענת את טפסיו באמצעות GET בלבד. הוספת עמוד מהמאגר טוענת רק את
  הטפסים שבעמוד, במקבצים של עד ארבע בקשות GET. תוצאת קריאה שנכשלה אינה
  מוחלפת בנתונים מדומים; מוצגת הודעה ונוספים רק טפסים שהתקבלו בפועל.
- דפדוף של 20 שורות, כותרת טבלה נצמדת ואזור גלילה תחום. סינון חריגים,
  ערכים ללא אישור אנושי מלא וערכים שאושרו אנושית. חריגה משותפת למספר
  התחייבויות נספרת פעם אחת, לפי מסמך/טופס/שדה.
- לחיצה על תא או על ״החריגה הבאה״ פותחת שדה אחד לביקורת, לצד המקור.
  אפשר לבדוק גם שדה שאינו מסומן. אין הצגה כפויה של שבעה עורכים.
- תיקון שדה משותף מופיע בכל שורות אותו טופס כטיוטה. רק תשובת שמירה תקינה
  הופכת אותו לתיקון שמור. IDs, זמן ההצהרה ובקשת השמירה נשמרים לשליחה חוזרת
  זהה במקרה של תשובה לא ידועה. גם טקסט שהוקלד בלי בחירת החלטה מוגן מהחלפה
  מקרית של המסמך.
- כל הטפסים המזוהים בשרת נשארים טפסים נפרדים; אין יצירת רשומת DB או אירוע
  ביקורת חדש לכל שורה חזותית. החלטה אחת לשדה משותף נשארת החלטה אחת.
- מיתוג ״מחויבים ל־100״ ללא ניקוד, סימן מסמך מקופל המשלב 100, favicon תואם,
  RTL, בידוד מזהים ב־LTR, מיקוד מקלדת, תוויות והפחתת תנועה.

השולחן הוא **מטמון עבודה לדפדפן הנוכחי**, לא אצווה שמורה במסד. רענון מאבד
את הרשימה והטיוטות המקומיות; רשומות שנשמרו בשרת נפתחות שוב מהמאגר ללא
חילוץ. מקורות וטיוטות אינם נשלחים לספק בעת פתיחה, סינון או ביקורת.

## מגבלות API מאומתות

### ביטחון וחריגים

`DemoWorkflow._project` מחזיר `provider_value_status`,
`provider_review_status`, `review_status`, ערכי מקור וערכים שנבדקו. הוא אינו
מחזיר confidence, signals, שגיאות אימות מפורטות או סתירות בין שדות.
לכן אין בממשק ״ביטחון גבוה״ או אחוזי ביטחון מומצאים. ערך רגיל מסומן
כ״חולץ״ עם הסבר שאינו אישור אנושי או הוכחת תקינות.

רק שדות שלא טופלו אנושית מודגשים: מקור חסר/לא קריא/עמום/טרם עובד, ערך
ריק, דגל בדיקה/הבהרה/דחייה מהספק, מצב ביקורת בלתי פתור או מצב לא מוכר.
אישור מפורש, תיקון מאושר או אישור שדה ריק מסירים את הדגל הנוכחי; המקור
וההיסטוריה אינם נכתבים מחדש. סטטוס ״אושר״ שמגיע מהספק אינו אישור אנושי.
ערך שגוי שהשרת לא סימן עשוי להישאר ללא דגל — זהו סיכון אינטגרציה מהותי.

### השלמת ביקורת

`ReviewedBusinessRecord.unresolved_fields` ו־`review_status` דורשים החלטה
לכל שבעת השדות. מותר לשמור רק חריגה אחת, אך הטופס נשאר `unresolved` אם
שדות אחרים לא אושרו. אין שינוי סטטוס מקומי שמדמה השלמה.

כדי לאפשר השלמה אמיתית על בסיס חריגים נדרש שינוי שרת מאושר: רשימת שדות
מחייבי ביקורת לפי מדיניות שרת עם גרסה ותיעוד, API שמחזיר דגלי שדה והסיבות,
ומצב קבלה לפי מדיניות הנבדל מאישור אנושי. השלמה וייצוא צריכים להסתמך על
אותה מדיניות. אין להסתמך על ביטחון עצמי של מודל כתקינות מאומתת.

### העלאת אצווה

`POST /api/v1/demo-runs` וגם `/extractions` מקבלים `UploadFile` יחיד.
אין בחירת קבצים מרובה או שליחה סדרתית אוטומטית. כל העלאה מחייבת פעולה
והסכמה מפורשת כפי שהיה קודם. ספירת הטבלה היא טפסים שנטענו, לא התקדמות
עיבוד של אצווה.

המינימום לאצווה אמיתית: endpoint המקבל קבצים מרובים ומחזיר מזהה אצווה
ומזהי מסמך/משימה, שמירה וסטטוס נפרד לכל מסמך באמצעות התשתית העמידה הקיימת,
GET להתקדמות/תוצאות עם pagination, מניעת כפילות והגבלת בקשות/ניסיונות,
ושמירת הסכמה, מגבלות גודל והרשאות לכל מסמך. רצוי projection מרוכז עם
סטטוסי שדות כדי להימנע מקריאת פירוט נפרדת לכל טופס.

## Excel — מגבלה שאסור להסתיר

ה־frontend עדיין קורא לאותו endpoint, עבור המסמך הפעיל, ולא מאחד את כל
שולחן העבודה לקובץ. טיוטות וערכים ללא אישור אינם נהפכים לערכי עסק מאושרים.
במדיניות השרת הקיימת שדות שלא אושרו נשארים ריקים בייצוא, גם אם מוצגים
כערכי מקור בטבלה.

נוסף לכך, `backend/services/excel_export.py` ב־HEAD של ה־worktree
(`01315c9`) עדיין מוסיף שורת עסק אחת לכל טופס עם מערך מספרי התחייבות.
תיקון הייצוא לשורה לכל התחייבות נמצא בשינויים הקודמים בעותק המקורי;
הוא לא הועתק ולא נערך כאן. אין לטעון שהטבלה מבטיחה את פריסת ה־XLSX בשרת
המחויב הזה. בחיבור לשרת המקורי עם התיקון, יש לאמת את גרסת השרת והקובץ
בבדיקת אינטגרציה נפרדת. לא נוצר XLSX אמיתי או שינוי מסד במשימה הזאת.

## בדיקה והפעלה — PowerShell מתוך ה־worktree

```powershell
npm --prefix .\frontend test
npm --prefix .\frontend run typecheck
npm --prefix .\frontend run build
git diff --check
node --experimental-strip-types .\frontend\tests\browser-smoke.ts
```

בדיקת הדפדפן מפעילה שרת MOCK בפורט loopback זמני משלה, בלי לעצור שרת
קיים. הפרופיל וצילומי המסך נשמרים בתיקיית `frontend/storage/` המתעלמת
מ־Git. אין צורך בהתקנה או בגישה חיצונית. אין lint מוגדר בפרויקט.

תוצאות ההרצה בפועל: **33 בדיקות עברו**, בדיקת טיפוסים ובניית ייצור עברו,
וגם `git diff --check`. בדיקות Chrome עברו ב־1440×1000 וב־390×844, עם 25
שורות התחייבות, דפדוף וסינון, חריגה אחת במקום שלושה עותקים, שמירת החלטה
יחידה בלי אישור שישה שדות נוספים, תיקון משותף לשלוש שורות, מקלדת, מיתוג,
הפחתת תנועה, הסכמה, כשל חילוץ ושגיאת ייצוא. יחידות נוספות בדקו 50 שורות
בדפדוף 20/20/10 ושמירת נתונים במקרה של כשל בקריאת טופס נוסף. צילומי המסך
נבדקו חזותית. אפס קריאות למסד, לספק או ל־API חיצוני.

הבנייה הראשונית נחסמה ב־sandbox עקב הרשאות קריאה של esbuild; אותה פקודה
עברה מחוץ ל־sandbox, ללא שינוי תצורת הבנייה. בדיקות PostgreSQL או XLSX
אמיתי לא הורצו; הן אינן חלק משרת ה־MOCK.

לסקירה ידנית סינתטית בלבד:

```powershell
node --experimental-strip-types .\frontend\tests\preview-server.ts
```

כתובת: **http://127.0.0.1:5174**. אם שרת preview ישן כבר פועל, יש לעצור
אותו ב־Ctrl+C בחלון שלו ולהפעיל מחדש; הוא לא נעצר במסגרת המשימה. מוצגים
שני טפסים סינתטיים, 25 התחייבויות ו־ID חסר בטופס השני. בחרו ״רשומות שמורות״
ואז ״צירוף העמוד לשולחן העבודה״, או פתחו רשומה. סננו ״עם דגל לטיפול״,
לחצו ״החריגה הבאה״, אשרו את השדה הריק עם הצהרה ונימוק, ושמרו. דגלי ה־ID
ייעלמו אך מצב הטופס יישאר ממתין. בדקו תיקון שם/תאריך והשפעתו על כל שורות
הטופס. הייצוא ב־preview מחזיר שגיאה מכוונת, ולא קובץ XLSX מדומה.

חלופה שמפעילה תצוגה חדשה ב־5175 בלי לעצור את השרת הקיים:

```powershell
node --experimental-strip-types -e "import('./frontend/tests/preview-server.ts').then(m => m.startPreview(5175)).then(p => console.log(p.origin))"
```

כתובת החלופה: **http://127.0.0.1:5175**. עצירה ב־Ctrl+C בחלון ההרצה.

חיבור לשרת היישום הקיים, ללא שינויו:

```powershell
npm --prefix .\frontend run dev
```

**http://127.0.0.1:5173**, עם backend קיים ב־8000. מדיניות Origin נשמרת;
אין לשנות אותה כדי לחבר פורט אחר. אין צורך בחילוץ חי כדי לפתוח רשומות
שמורות. ההעלאה לשירות חי אינה חלק מאישור המשימה הזאת.
