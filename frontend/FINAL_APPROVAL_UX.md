# אישור טופס מתוך טבלת ההתחייבויות

התיקון נמצא בעץ הפרימיום בלבד. לא שונו backend, חוזי ביקורת, מסד, מיגרציות,
הגדרות סביבה, ספק או ייצוא. שינויים קודמים נשמרו; אין commit או push.

## התנהגות

- עמודת פעולות בתחילת כל שורה, בצד ימין של טבלת RTL: אישור סופי, בדיקת
  חריגות או אושר סופית. פעולות השורה חלות על אותו זוג מסמך/טופס בכל שורותיו.
- לפני פתיחת אישור מתבצע רענון מהשרת. זכאות מבוססת על דגלי המדיניות שהשרת
  החזיר ועל היעדר טיוטות בטופס הנבחר, ולא על צבע תא או היעדר נתונים.
- טופס חסום פותח ביקורת ממוקדת בשדות החוסמים ובטיוטות; נשמרים הנימוקים
  המפורשים מהשרת. לחיצה על תא מאפשרת גם תיקון שדה אחר, כולל אחרי אישור.
- האישור משתמש בחלון `dialog` מקורי עם תיאור היקף ומספר ההתחייבויות בכל
  הטופס, גם מעבר לעמוד הנוכחי. נדרשים פרטי בודק והצהרה שאינה מסומנת מראש.
  Tab נשאר בחלון; Escape וסגירה מחזירים פוקוס לפעולת השורה.
- בשגרה נשלחת בקשת finalize אחת, ולא בקשה לכל התחייבות. חסימת לחיצה כפולה
  מתבצעת גם לפני עדכון React. תוצאה לא ידועה שומרת את הבקשה המקורית לצורך
  ניסיון אימות עם אותם מזהים, זמן וגרסה; אין יצירת החלטות שדה בדפדפן.
- הצלחה מוצגת רק אחרי תשובת השרת. אחריה מתבצע GET נוסף וכל שורות אותו
  טופס מתעדכנות. אם GET נכשל אחרי POST מוצלח, מוצגת במפורש הצלחת השמירה
  וכשל הרענון; לא נשלחת בקשת אישור נוספת אוטומטית.

הוסר אזור האישור הדביק הגבוה והגלילה הפנימית שלו. גם תצוגת המקור נמצאת
בזרימה רגילה. רק חלון האישור משתמש בשכבת modal; טבלת הנתונים שומרת גלילה
מוגדרת ונגישה בפני עצמה. בטבלה רחבה גוללים אופקית לשדות; עמודת הפעולות
מופיעה ראשונה ב־RTL. לא נוצר שיוך חדש בין מספרי דגימות להתחייבויות.

## אימות שבוצע

- 43 בדיקות frontend עברו, כולל שורות משותפות, 30 התחייבויות בשני עמודים,
  טיוטות בטופס אחר, חסם תאריך, גרסאות ישנות, כשלי רשת ולחיצה כפולה.
- TypeScript ובניית production עברו.
- React→FastAPI→XLSX עבר עם הספק המדומה: שני טפסים, שני אירועי אישור טופס,
  ארבע שורות התחייבות ופתיחה חוזרת. שלוש החלטות השדה האמיתיות נשמרו בנפרד.
- Chrome עבר ב־1440, 1024, 390 ו־320 פיקסלים. נבדקו אי־חפיפה, התאמת החלון
  והפקדים למסך, מחזור פוקוס, Escape והחזרת פוקוס. צילומים נשמרים תחת
  `frontend/storage/browser-<timestamp>/`; זו תיקייה מקומית מוחרגת מ־Git.

הבדיקות משתמשות בנתונים סינתטיים בלבד. שרת תצוגת Chrome הוא fixture מסומן;
בדיקת FastAPI נפרדת משתמשת בשרת ובחוזי הביקורת האמיתיים. אין במסלולים אלו
PostgreSQL, Gemini או רשת חיצונית. לא בוצעה בדיקת ייצור או restart למסד.

## פקודות

משורש העץ המקורי:

```powershell
npm --prefix .\storage\premium-ui-worktree\frontend test
npm --prefix .\storage\premium-ui-worktree\frontend run typecheck
npm --prefix .\storage\premium-ui-worktree\frontend run build
node --experimental-strip-types .\storage\premium-ui-worktree\frontend\tests\form-approval-e2e.ts
node --experimental-strip-types .\storage\premium-ui-worktree\frontend\tests\browser-smoke.ts
```

להצגה מול השרת המקומי הקיים, בלי להפעיל חילוץ:

```powershell
npm --prefix .\storage\premium-ui-worktree\frontend run dev
```

פתחו http://127.0.0.1:5173, פתחו רשומה שמורה, ובחרו פעולת שורה. בחריגות,
תקנו ושמרו דרך הביקורת הקיימת. באישור, בדקו את המקור ואת היקף הטופס,
מלאו הצהרה וסמנו אותה במפורש. ודאו שכל השורות הקשורות מתעדכנות, פתחו
מחדש וייצאו לפי הצורך. בדיקה ידנית של אישור משנה את הרשומה הנבחרת;
הבדיקות האוטומטיות לא שינו רשומות עסקיות.
