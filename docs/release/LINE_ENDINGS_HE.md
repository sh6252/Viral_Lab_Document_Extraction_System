# מדיניות סיומי שורות ואימות אריזת השחרור

בבדיקה לפני הפרסום נמצא שהמניפסט הקודם חושב מבתי קבצים מקומיים ב־Windows.
הגדרת המערכת `core.autocrlf=true` הייתה ממירה CRLF ל־LF בעת הוספה ל־Git:
132 קבצים היו משתנים, ובהם המניפסט עצמו; 131 קבצים בעלי SHA-256 במניפסט
לא היו תואמים ל־Git blobs. לכן ניסיון הפרסום הקודם נעצר ללא staging או commit.

התיקון מוגבל לעץ `storage/submission-release`. `.gitattributes` מגדיר
`* text=auto eol=lf`, עם `binary -text` מפורש עבור PDF, תמונות, ארכיונים,
Excel וגופנים. טקסט נשמר ב־LF גם ב־Git וגם ב־checkout, ללא שינוי בהגדרות Git
גלובליות. הקבצים המקומיים הכלולים ברשימת השחרור נורמלו רק מ־CRLF ל־LF;
ה־PDF הסינתטי היחיד נשמר בדיוק. לא שונו כללי החילוץ או התנהגות היישום.

`source-files.json` מכיל SHA-256 של הבתים הקנוניים בפועל, ללא hash עצמי.
`scripts/release_snapshot.py` בודק תחילה את הקבצים מול המניפסט, ומשווה
`git hash-object --no-filters` לתוצאת clean הרגילה ללא כתיבת objects.
שינוי של Git עקב סיומי שורות או filter גורם לכישלון; הכלי אינו מנרמל בשקט.
ארכיון מקור חדש, אם יופק, יכיל בדיוק את הבתים המאומתים האלה.

לאחר staging מפורש של הרשימה המאושרת, הפקודה הבאה בודקת גם שאין קובץ
חסר או נוסף ב־index, ושכל blob שנקרא באמצעות `git cat-file --batch` זהה
לקובץ המאומת, כולל המניפסט עצמו:

```powershell
python scripts/release_snapshot.py --git-index
```

בדיקות האריזה מכסות שינוי מקור, CRLF בעל hash מקומי תקין אך blob שונה,
filter מותאם, אי־התאמה של תוכן staged, קובץ staged נוסף, checkout עם
`core.autocrlf=true`, שימור בתים בינאריים וארכיון דטרמיניסטי ללא דריסה.
בדיקות אלה משתמשות במאגרים זמניים בלבד.

`integration-manifest.json` ו־`cloud-changes.json` הם תיעוד היסטורי של
שלבי ההכנה הקודמים: ה־hashes הפנימיים שלהם מתייחסים לבתים לפני הנרמול.
הם נשמרו כעדות, ולא שוכתבו כדי להציג כאילו הבתים המקוריים היו LF.
רשימת הקבצים הקנונית העדכנית היא `source-files.json`; גם שני קובצי התיעוד
ההיסטוריים עצמם נכללים בה. ארכיונים מקומיים קודמים לא נדרסו ואינם חלק מה־Git.

מסמכי ההכנה האחרים מתארים בדיקות ומגבלות של המועמד לפני הפרסום. פרסום
הענף ל־GitHub אינו פריסה ל־Render, אינו אישור ל־Gemini ואינו חיבור ל־Neon.
חסם המקור הסינתטי העמיד המתועד ב־`RENDER_NEON_HE.md` נותר בעינו.

תוצאות בדיקות ההכנה לפרסום: 28 בדיקות אריזה עברו; 198 קובצי מקור
ברשימה המדויקת; אפס הבדלים בין בתים מקומיים לתוצאת clean. סריקת כל
התכולה לא מצאה חתימות של מפתחות או סודות פעילים. 43 התאמות חשודות של
DSN, סיסמה או token נבדקו: כולן placeholders בתיעוד, ערכי בדיקה סינתטיים
או קוד המגדיר משתנים; אין בהן פרטי גישה אמיתיים. שמות ארטיפקטים המופיעים
בדוחות היסטוריים אינם הקבצים עצמם. רק ה־PDF הסינתטי הקפוא נכלל כמסמך.
קובצי `.env` אמיתיים, גיבויים, ZIP, תוצרי בדיקות ו־node_modules מחוץ לרשימה.
